# Release Guide

This guide explains how to create a new Pack3d release.

## Prerequisites

- Write access to the repository
- Your local `main` (or `master`) branch up to date with the latest changes

## Release assets

Each release includes:

- **pack3d_v{version}** - Linux amd64 binary (statically linked, CGO disabled)
- **Source code (zip)** - Auto-generated by GitHub
- **Source code (tar.gz)** - Auto-generated by GitHub

## How to release

### 1. Update the version in code

Edit `cmd/pack3d/main.go` and set the `VERSION` constant to match the release (e.g. `"1.6.1"`).

### 2. Commit and push

```bash
git add cmd/pack3d/main.go
git commit -m "Release v1.6.1"
git push origin main
```

### 3. Create and push the tag

Create an annotated tag and push it. The release workflow triggers on tags matching `v*`.

```bash
git tag -a v1.6.1 -m "Pack3d v1.6.1"
git push origin v1.6.1
```

### 4. Verify the release

1. Go to the repository's **Releases** page on GitHub
2. The new release should appear with auto-generated release notes
3. Confirm the assets: `pack3d_v{version}`, Source code (zip), Source code (tar.gz)

## CI workflows

- **Build** (`.github/workflows/build.yaml`): Runs on push/PR to main; verifies the project compiles
- **Release** (`.github/workflows/release.yaml`): Runs when a `v*` tag is pushed; builds the linux binary and creates the GitHub release

## Troubleshooting

- **Release not created**: Ensure the tag matches `v*` (e.g. `v1.6.1`, not `1.6.1`)
- **Workflow failed**: Check the Actions tab for logs; common causes include build failures or permission issues
- **Wrong version in binary**: The binary filename uses the tag (e.g. `v1.6.1` -> `pack3d_v1.6.1`). Ensure the tag and `VERSION` in main.go match
